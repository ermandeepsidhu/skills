# AGENTS.md

Guidance for AI agents working **in this repository**. (Claude Code reads `CLAUDE.md`, which
imports this file; Cursor, Copilot, Codex, and others read `AGENTS.md` directly.)

## What this repo is

A public library of high-quality, reusable **skills** for engineering teams. Each skill is a
self-contained directory that teaches an agent how to perform one task well. Canonical skills
live under `skills/<domain>/<category>/<skill>/`. Treat
`skills/engineering/architecture/drawio-architecture/` as the **reference template** — match
its structure and rigor when adding a new skill. See `README.md` for the full catalog.

These skills are distributed across multiple AI coding tools via the open Agent Skills
`SKILL.md` standard. The canonical copy lives once under `skills/`; per-tool directories
(`.claude/skills/`, `.cursor/skills/`, `.github/skills/`, `.agent/skills/`, `.agents/skills/`)
are **flat symlink farms** generated by `scripts/skills.py`. Never hand-edit those symlinks —
edit the canonical skill and run `python3 scripts/skills.py sync`.

## Skill anatomy

A skill is a directory whose contract is its `SKILL.md`:

- `SKILL.md` — required. YAML frontmatter with exactly `name` (must equal the directory name)
  and `description`, then a numbered, ordered **workflow** body. The `description` is the
  trigger: it states *when* to use the skill and what it produces. Keep the workflow
  imperative and step-ordered (e.g. Clarify → Plan → Emit → Verify → Deliver).
- `references/` — deep-dive docs the workflow points to (syntax primers, conventions,
  verification procedures) plus any executable tooling. Loaded on demand, not inlined.
- `assets/` — reusable verbatim material the agent copies into its output (e.g. style strings).
- `examples/` — worked, *validated* outputs to pattern-match against. Anything in `examples/`
  must itself pass the skill's own verification. Rendered previews accompany the source files.
- `EXAMPLES.md` — a prompt → output showcase for humans browsing the skill.

A skill must **degrade gracefully**: the always-on verification tier depends only on the
language standard library (no GUI, no network), and richer checks layer on only when optional
tooling is present. See `skills/engineering/architecture/drawio-architecture/references/verification.md`.

## Commands

Run the `drawio-architecture` validator's test suite (Python 3 standard library, `unittest` —
no third-party packages):

```bash
cd skills/engineering/architecture/drawio-architecture/references
python3 -m unittest discover -s tests -v
```

Validate a `.drawio` file (zero-dependency, the skill's always-on check):

```bash
python3 skills/engineering/architecture/drawio-architecture/references/validate.py <file>.drawio
```

Maintain the repo:

```bash
python3 scripts/skills.py sync     # refresh per-tool symlink farms
python3 scripts/skills.py check    # CI gate: symlinks present + every skill named in README.md
python3 scripts/render-examples.py # build draw.io-viewer HTML for example previews
```

`validate.py` is intentionally dependency-free (only `xml.etree`); keep it that way. Its tests
use fixtures in `references/tests/fixtures/` — `good.drawio` must stay valid, and each
`bad_*.drawio` fixture pins one failure mode (overlap, dangling edge, missing id).

## drawio-architecture specifics

The skill hand-authors native `.drawio` (mxGraph) XML. Two invariants make output reliable;
preserve them when editing the skill or its examples:

- **Deterministic grid layout.** Coordinates are *computed*, never guessed, from a
  `(column, tier)` position using fixed constants (`NODE_W=160, NODE_H=80, H_GAP=80,
  V_GAP=120, MARGIN=40`). This guarantees no overlaps. The full math, including the boundary
  bounding-box + `BOUNDARY_PAD=24` derivation, is in `references/c4-conventions.md`.
- **C4-inspired conventions.** Vendor-neutral role palette and typed labels live in
  `assets/styles.md`; every relationship edge carries a verb label; boundaries are emitted
  *before* their children (so they render behind); children use coordinates relative to the
  boundary origin.

If you change the grid constants, the style strings, or the boundary math, re-validate every
file in `examples/` and update the worked examples in `references/c4-conventions.md` to stay
consistent.

## How skills are developed

Design specs and implementation plans for skills live under `docs/superpowers/` (`specs/` and
`plans/`, dated). New skills are authored with the `superpowers:writing-skills` methodology —
invoke that skill before creating or substantially editing a skill. When you add or rename a
skill, update `README.md`'s catalog and run `scripts/skills.py sync` + `check`.
